Transformer 架构


encoder和decoder
编码器负责处理原始文本以及深入理解该段落的语境和含义

解码器则利用对德语段落的深刻理解 生成对应的英文版本

大多数大语言模型只包含第二个解码器部分，因为他们只关注文本生成任务

而编码器通常用于嵌入模型内部，因为其目标是构建丰富的文本语义表示

让我们追踪一下提示词在大语言模型中的流转过程，也就是在Transformer解码器部分的流转过程：
1. 提示词会被分割为若干个Token(看分词器如何安排)
2. 每个Token都会被分配一个初始的稠密向量表示，这个向量基本上是对该Token含义的首次猜测。这些猜测是静态的。所以每次输入相同的Token，它都会被分配同样的初始向量。
3. 接下来每个Token会获得一个位置向量， 用于表示其在提示词中的位置
![Token&Vector](./token2vector.png)
4. 当这些初始嵌入向量和位置向量被创建后，它们会被送去进一步处理，此时Token进入了Transformer的注意力机制, 每个Token实际上会关注提示词中的所有其他Token并能感知它们的含义和位置。每个Token会决定自己应该最关注哪些其他Token。注意力机制本质上就是确定哪些Token对我的含义影响最大
例如：The brown dog sat next to the red forx. dog更关注brown和sat
5. 分配注意力的机制被称为注意力头，而大多数模型实际上包含多个注意力头，分别专注于不同类型的词语关系，你可以把其中一个注意力头理解为专注于对象与描述之间关系的头。因此单词fox可以能会把全部注意力集中在brown上。另一个注意力头则可能专注于对象之间的空间关系，在这个头上fox可能会更多关注sat和next，实际上每个注意力头所捕捉的关系并不是由人类预先设定的明确关系集。而是在模型训练过程中自动学习到的复杂且抽象的关系。
6. 较小的模型可能会使用8到16个注意力头，而更大的模型可能会使用超过100个注意力头。
7. 这之所以重要是因为每个标记不仅跟踪它与文本中其他所有标记的关系，而且它们会在许多不同的注意力头中重复进行这一过程。每一次关注时都会带有略微不同的视角或侧重点。
8. 最终注意力机制能够对所有标记之间的关系形成非常详细的表示文本中所有标记之间的关系。
9. 一旦每个标记都分配好了所有的注意力分数，信息就会进入前馈网络
```text
Input Embeddings -> Attention -> Feed Forward
```
前馈阶段是大语言模型中规模最大的部分，也就是说 这一部分包含了最多的参数
基于每个标记最初的嵌入表示位置以及注意力分数，它会为每个标记分配更新后的向量嵌入。 这些新向量本质上是对每个标记真实含义的再次猜测。
eg： dog [0.65, 0.4, 0.87, 0.22, 0.41]
first guess: dog is an animal
eg： dog [0.38, 0.19, 0.26, 0.41, 0.22]
second guess: dog is a brown animal that sat near a red fox
但现在 这些向量已经结合了文本中其他标记的上下文信息。
大多数大语言模型会重复整个处理流程，这些再次猜测的向量会被送回注意力和前馈机制，从而生成每个标记含义更为精细的第三次猜测向量，一个典型的大语言模型会将这些向量在各层间传递8道64次不等，在每个阶段逐步提升对文本的理解，现在多语言模型已经准备好开始生成内容了
![llm](./llm.png)
10. 基于它生成的高度精细化向量嵌入，模型会根据训练数据提出问题，下一个最优可能出现的标记是什么？ 这会以概率分布的形式计算在模型此表中的所有标记，通常只有少数几个标记有较高的出现概率，但如果你的模型能识别十万个标记，每个标记都会被分配一个概率，即使绝大多数概率几乎为零，最后大语言模型会从这个概率分布中选出一个标记，每个标记被选中的概率都参与加权，概率较高的标记被选中的频率更高，但理论上任何标记都有极小的被选中机会。 将在后续内容中学习如何调整这些概率以及模型如何选择新标记。被选中的标记会被添加到提示词末尾，经过所有这些步骤，大语言模型就生成了一个新标记
11. 如果想生成第二个标记，模型必须重新执行整个流程，只不过这次要同时考虑原有标记和新添加的标记。这样可以确保新标记在原始标记和已生成标记的上下文中都合理，这意味着早起随机选择的标记也会影响后续标记的选择。
12. 要生成完整的补全内容，模型会不断重复这个流程，直到达到你为补全设置的标记上限或者模型选择生成一个特殊的补全结束标记，表示任务完成。
13. 大语言模型生成的标记可能用于补全短语或回答问题，但无论用途如何，这些标记都可以被解码为普通文本并返回给用户，这就是大语言模型的整个流程

大语言模型采样策略

理解并控制分布曲线是调整大模型行为的重要部分
接下来我们来看几种实现这一目标的策略
一种简单的方法是让大模型不要随机选择，而是十种选取概率最高的词元，这被称为贪婪解码，贪婪解码的主要优点是让大模型具有确定性。如果你给模型相同的提示，它每次都会生成相同的回复，贪婪解码的主要缺点是生成的文本，往往会变得可预测，结果可能显得很普通 甚至有些生硬，贪婪解码的另一个问题是大模型有时会陷入不断重复同一词序的循环，大模型其实并不关心整体补全是否合理，它只是不断选择概率最高的下一个词元，一旦模型进入重复循环，就没有机制能它跳出来，尽管存在这些潜在不足，贪婪解码在需要高度可预测和确定性输出时很有用。比如代码补全或临时用于系统调试
在大多数情况下 你并不希望完全消除随机性，你只是想对其进行控制，控制大语言模型随机性的最常用参数叫做温度，你可以把温度理解为调节概率分布形状旋钮，默认温度为1时，就是原始概率分布，较低温度会让分布变得更尖锐，只有最可能的词元才有机会被生成，词元的排序不会变，但被选中的概率会发生变化，温度设为零时， 模型就会执行贪婪解码，只有最可能的词元概率为百分之百，温度稍微调高一点， 例如在1.1-1.3之间，会让概率分布变得更平衡，不太可能的词元也有更多机会被选中，这样会带来更多变化，有时文本也更有趣或更具创意
