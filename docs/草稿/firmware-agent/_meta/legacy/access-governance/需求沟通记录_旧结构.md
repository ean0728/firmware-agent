## COM-0002 · AI 理解摘要

- 时间：2026-08-13T00:00:00+08:00
- 类型：understanding-proposal
- 状态：awaiting-user-confirmation
- 操作：OP-0002

### 当前理解

1. 本主题定义企业级 RAG + Harness 平台的用户与访问治理产品规则，适用于固件、上位机、半导体和制造业知识协作场景；范围覆盖身份、组织、部门、项目、知识库、文档、授权、审批、审计以及 RAG 检索前的权限收敛。
2. User 是全局身份，可属于多个 Organization 和任意多个 Department；Organization 是资源最终所有权与默认隔离边界；Project 是独立协作实体，可纳入跨组织成员，但不因此获得所属组织其他资源权限。
3. KnowledgeBase 归属于一个 Organization；Document 归属于一个 KnowledgeBase。知识库可向 Organization、Department、Project 或 User 授权。Document 默认继承知识库权限，并允许文档级授权和 blocked 覆盖；撤销仅移除相应授权路径。
4. 授权决策与审批流程分离：权限关系由 OpenFGA 统一决策，业务记录、审批与审计由平台保存。审批完成但授权关系尚未写入时，必须以可恢复状态表现，而不能将其等同于已生效权限。
5. Admin 需要管理组织、部门、用户、项目、知识库、共享授权、审批策略、权限来源解释与审计日志；每个受保护操作由服务端授权，前端能力展示不构成安全边界。
6. RAG 检索必须先取得用户在当前组织上下文可访问的 KnowledgeBase/Document 范围，再传入检索过滤；LLM、日志与评估不得接触越权知识内容。
7. 本主题不包含完整 HR/OA、Team、通用 BPMN、任意动态权限 DSL、OpenFGA DSL/数据库 DDL/API 的实现细节，以及页面布局与视觉规范。

### AI 提议但未确认

- 文档将用“治理与上下文”“知识访问与例外”“共享、审批与生效”“管理与审计”“RAG 权限联动”组织，而不直接照搬原始系统设计章节。
- 对已被原始材料标注为“后续策略配置”但尚未有默认结果的行为，保留为开放问题，不写成产品事实。

### 待确认

- Q-0001（Blocker）：组织 owner/admin 对组织内敏感 KnowledgeBase 的默认读取权是“无默认读取、必须有资源授权”，还是允许通过可配置策略默认读取？这会决定敏感知识库的权限来源解释与管理入口。
- Q-0002（Blocker）：Approval Request 已 `approved` 但 OpenFGA 写入失败时，申请人和审批人看到什么状态、谁可重试、是否允许撤回或人工修复？这会决定审批中心、授权详情和失败恢复原型。
- Q-0003（Blocker）：Project 进入 `completed/archived` 时，通过 Project 取得的既有 KB/Document 授权默认继续有效、立即撤销，还是由项目/组织策略决定？这会决定项目状态变化与访问结果。

### 确认后拟更新

- 新增 R-0001 至 R-0017：范围、身份与组织上下文、项目协作、资产所有权、授权与覆盖、共享撤销、审批、后台治理、审计、RAG 权限联动及安全边界。
- 新增 DEC-0001 至 DEC-0004：组织资产边界、Project 跨组织协作、Document 继承与覆盖、固定权限模型/动态关系。

## COM-0005 · AI 对修改意见的理解摘要

- 时间：2026-08-13T16:24:13+08:00
- 类型：understanding-proposal
- 状态：awaiting-user-confirmation
- 操作：OP-0004
- 基于：COM-0004

### 当前理解

1. 当前目标是开源版本；用户账户不通过邀请流程产生，只能由具备用户管理能力的 Admin 在后台直接创建。
2. Admin 创建用户时需要设置该用户的登录密码；创建后，Admin 可以为用户设置新密码。
3. 普通用户没有修改本人密码的权限和入口。
4. v0.1 中“邀请用户”和 pending 邀请/待加入语义需要移出，用户创建成功后采用什么初始状态将在后续修改中与既有用户状态规则统一。

### 本轮变化

- 替换：Admin 用户管理从“邀请用户”改为“直接创建用户”。
- 新增：Admin 设置初始密码、Admin 修改用户密码。
- 限制：普通用户不能修改本人密码。
- 暂不改变：组织/部门归属、账户停用与恢复、权限和审计等其他规则。

### 待确认

- Q-0004（Major）：普通用户是否也没有“忘记密码/自助重置密码”能力，即忘记密码后只能联系 Admin 由 Admin 设置新密码？这会决定登录页、个人设置和管理员用户详情中的操作与反馈。

### 确认后拟更新

- 修改 R-0003、R-0014，并增加密码管理的独立需求事实。
- 将“邀请用户”明确移出开源版范围。
- 更新 TR-ACTOR、TR-INPUT、TR-FLOW、TR-RISK、TR-FEEDBACK。
- 仅更新沟通证据和需求账本；除非用户另行明确要求生成，否则不创建新需求版本。
