# 需求账本

**摘要**：顶部是当前有效产品事实，底部是账本修订历史。

## 当前有效需求

### R-0001 · 用户与访问治理范围

- 状态：confirmed
- 需求：平台应统一管理用户身份与生命周期、Organization、Department、Project 成员关系、KnowledgeBase/Document 所有权与访问、共享授权、审批、审计以及 RAG 检索访问范围。
- 来源：COM-0003、SRC-0001 §1
- Figma影响：需要表达用户治理、组织协作、资源授权、审批查询和审计等核心任务；不得把用户系统缩减为单一 RBAC 配置页。
- 依赖：none
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0002 · 全局用户与组织上下文

- 状态：confirmed
- 需求：User 是平台全局身份，可加入多个 Organization；同一用户在不同 Organization 中可具有不同组织角色。涉及组织资源的任务必须具有明确的当前 Organization 上下文。
- 来源：COM-0003、SRC-0001 §4
- Figma影响：需要让用户识别并切换当前组织，并在组织上下文不明确或无效时阻止继续操作。
- 依赖：R-0003
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0003 · 用户生命周期与失效结果

- 状态：confirmed
- 需求：开源版不使用邀请或待加入流程，用户状态至少包括 active、suspended、disabled。平台级 Admin 创建用户成功后，账户立即进入 active；active 可按当前组织和资源授权访问，suspended 拒绝业务访问但保留历史关系，disabled 不可登录且保留历史审计。
- 来源：COM-0003、COM-0006、COM-0007、SRC-0001 §4.1
- Figma影响：用户管理不应出现邀请、pending 加入或创建后再次启用步骤；创建成功反馈和用户列表应显示 active。仍需呈现其他账户状态、允许的平台级治理操作及停用后的访问结果。
- 依赖：R-0002、R-0015
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0003

### R-0004 · 组织角色与资源权限分离

- 状态：confirmed
- 需求：Organization 角色至少包括 owner、admin、member、guest；组织治理角色不自动等同于 KnowledgeBase/Document 读取权限。未建立可证明授权路径时默认拒绝访问。
- 来源：COM-0003、SRC-0001 §4.2、§19
- Figma影响：组织治理能力和知识内容访问能力必须分开表达；权限查询需要说明实际授权来源。
- 依赖：R-0002、R-0008
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0005 · 部门层级与多部门归属

- 状态：confirmed
- 需求：Department 表示 Organization 内可多级嵌套的正式组织单元；同一用户可同时属于任意多个 Department。部门负责人用于审批、治理和展示，不因负责人身份自动获得部门全部知识读取权。Department 存在有效授权时不得直接归档，具备归档权限的管理员必须先查看影响并迁移、转换或撤销全部有效授权。
- 来源：COM-0003、COM-0008、SRC-0001 §5
- Figma影响：部门管理需要支持层级浏览、成员多归属和负责人管理，同时避免将负责人展示为隐含知识权限；归档任务需要展示有效授权影响并在未处理完前阻止归档。
- 依赖：R-0004、R-0008
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0006 · 项目作为跨组织协作边界

- 状态：confirmed
- 需求：Project 是归属于一个 Organization 的独立协作实体，具有负责人、成员、访客及生命周期状态；可直接纳入其他 Organization 的 external member。加入 Project 只建立项目成员关系，不自动获得项目所属 Organization 的其他资源权限。Project 进入 completed 后保留既有项目来源授权但禁止新增；进入 archived 后撤销项目来源授权，其他独立授权路径继续按自身规则生效。
- 来源：COM-0003、COM-0008、SRC-0001 §6
- Figma影响：项目成员管理需要区分 internal/external，并明确“加入项目”和“获得知识访问”是两个独立结果；项目状态变更需要展示新增授权限制或撤销影响。
- 依赖：R-0002、R-0008
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0007 · 知识资产所有权

- 状态：confirmed
- 需求：KnowledgeBase 和 Project 最终归属于 Organization；Document 必须属于一个 KnowledgeBase，并通过该 KnowledgeBase 归属于 Organization。Project 可关联或被授权访问 KnowledgeBase，但项目结束不转移或消灭组织知识资产。
- 来源：COM-0003、SRC-0001 §2、§6.1、§7
- Figma影响：资源详情与关联操作必须区分资产所有者、负责人、关联项目和获授权主体。
- 依赖：R-0006
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0008 · 知识资源角色与授权对象

- 状态：confirmed
- 需求：KnowledgeBase 至少支持 viewer、editor、manager 和 blocked 语义；可将权限授予 Organization、Department、Project 或 User。viewer 可查看；editor 在查看基础上可编辑与上传；manager 可管理共享和权限；blocked 表示显式拒绝。
- 来源：COM-0003、SRC-0001 §8
- Figma影响：授权任务必须让管理员选择授权对象类型、具体对象、权限级别及可选有效期，并清晰表达 blocked 的拒绝效果。
- 依赖：R-0004、R-0005、R-0006、R-0007
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0009 · 多路径权限与来源解释

- 状态：confirmed
- 需求：同一用户可以通过组织、部门、项目、直接授权和文档继承等多个路径获得权限；最终访问由全部有效关系共同决定。管理员必须能够查询用户或主体对资源的有效能力及主要来源。
- 来源：COM-0003、SRC-0001 §8.3、§12
- Figma影响：权限查询不能只显示一个角色，需要展示有效能力、来源路径、拒绝原因和仍然有效的其他路径。
- 依赖：R-0008、R-0010
- 冲突：none
- 替代：none

- 最后变更：L-0001

### R-0010 · 文档权限继承与例外

- 状态：confirmed
- 需求：Document 默认继承所属 KnowledgeBase 的权限；允许文档级直接授权、权限提高和 blocked。账号或组织上下文无效时直接拒绝；Document blocked 优先拒绝该文档；KnowledgeBase blocked 默认不能被文档直授权反向解除。
- 来源：COM-0003、SRC-0001 §10
- Figma影响：文档权限页需要同时表达继承来源、文档级例外、显式屏蔽和最终结果，避免用户误认为修改文档权限会改变资产所有权。
- 依赖：R-0007、R-0008、R-0009
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0011 · 共享、有效期与撤销

- 状态：confirmed
- 需求：共享不转移资源所有权；Grant 可设置有效期并可撤销。撤销或到期只移除对应授权路径，主体通过其他路径取得的权限继续有效。用户退出 Department、Project 或 Organization 后，应失去通过相应成员关系获得的权限。Project completed 后不得新增项目来源 Grant，archived 后撤销项目来源 Grant。Department 归档前必须先迁移、转换或撤销其有效 Grant。viewer/editor 默认不能二次转授权。
- 来源：COM-0003、COM-0008、SRC-0001 §9、§13.2
- Figma影响：共享详情、撤销确认和结果反馈必须显示准确影响范围，并在其他路径仍有效时明确告知用户仍具有什么权限；项目和部门生命周期操作需要展示相关 Grant 的限制、影响和处置进度。
- 依赖：R-0009
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0012 · 可配置审批与默认策略

- 状态：confirmed
- 需求：授权决策与授权审批相互分离。平台必须提供始终可用的默认审批策略，并允许管理员按 Organization、资源类型、授权目标类型和权限级别配置更具体策略。跨组织及敏感文档授权应按匹配策略进入一个或多个审批步骤。
- 来源：COM-0003、SRC-0001 §11.1、§11.2
- Figma影响：审批策略配置需要表达适用范围、匹配条件、审批步骤和优先关系；发起共享时应能识别是直接生效还是需要审批。
- 依赖：R-0008、R-0011
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0001

### R-0013 · 审批状态与权限生效分离

- 状态：confirmed
- 需求：Approval Request 至少支持 draft、pending、approved、applied、rejected、cancelled、expired；approved 只表示审批通过，applied 才表示授权关系写入成功并已生效。授权写入失败时必须保留可识别、可恢复的失败状态。平台级 Admin 可重试、终止或转交全平台失败任务，Organization owner/admin 可处理本组织失败任务；申请人和审批人只能查看失败信息与处理结果。
- 来源：COM-0003、COM-0008、SRC-0001 §11.3、§17.1
- Figma影响：审批中心与授权详情必须区分“已批准”和“已生效”，展示失败原因、处理状态和结果；仅向有处理权限的角色提供重试、终止和转交入口。
- 依赖：R-0012
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0014 · 管理后台能力

- 状态：confirmed
- 需求：Admin 后台首版应覆盖组织、部门、用户、项目、知识库、共享授权、审批中心、审批策略、权限查询和审计日志。平台级 Admin 负责全局用户账户创建和密码管理，并可处理全平台授权生效失败；Organization owner/admin 可处理本组织授权生效失败和 Department 归档前的授权处置，但不具备全局账户管理能力。前端可按服务端 capabilities 控制入口和操作可见性，但前端隐藏不是安全边界。
- 来源：COM-0003、COM-0006、COM-0008、SRC-0001 §12
- Figma影响：首版原型需要区分平台级与组织级管理范围，分别呈现账户管理、授权失败恢复和 Department 归档授权处置入口；页面结构、导航承载和组件形式由 Figma 决定。
- 依赖：R-0002–R-0013、R-0015、R-0018
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0016 · RAG 检索前权限收敛

- 状态：confirmed
- 需求：每次 RAG 查询必须先根据用户身份、当前 Organization 及有效授权得到可访问的 KnowledgeBase/Document 范围，再在检索阶段限制召回；不得先让模型接触全库内容再做结果过滤。权限边界同样适用于 RAG 日志和 Evaluation 数据。授权服务不可用时，RAG 查询拒绝执行，不使用缓存允许结果降级放行。
- 来源：COM-0003、COM-0008、SRC-0001 §18
- Figma影响：用户查询和知识选择体验需要服从当前组织与授权范围；无可访问知识、权限变化、授权服务不可用和被拒绝访问时应给出一致且可理解的结果。
- 依赖：R-0002、R-0009、R-0010
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0017 · 安全与一致性边界

- 状态：confirmed
- 需求：Organization 是默认隔离边界；所有受保护操作必须由服务端根据可信身份和组织上下文进行授权。授权服务不可用时，所有受保护的写操作、只读页面、API 和 RAG 查询均默认拒绝，不使用缓存允许结果降级放行。授权撤销、成员退出和 blocked 等变化应尽快影响访问结果；权限缓存不得延迟高风险撤销的生效。
- 来源：COM-0003、COM-0008、SRC-0001 §19
- Figma影响：无权限、上下文失效、授权检查不可用和权限刚发生变化时，需要明确且一致的阻止与恢复反馈；授权服务故障应显示暂时不可用而非误导为资源不存在。
- 依赖：R-0002、R-0003、R-0008、R-0011
- 冲突：none
- 替代：none
- 首次进入：L-0001
- 最后变更：L-0004

### R-0018 · 平台级账户与密码管理

- 状态：confirmed
- 需求：开源版用户账户只能由平台级 Admin 在后台直接创建；创建时由平台级 Admin 设置登录密码，创建成功后账户立即 active。创建后也只有平台级 Admin 可以为用户设置新密码。Organization admin 无权创建平台全局用户或修改全局用户密码。普通用户不能修改本人密码，不提供忘记密码或自助重置密码能力；忘记密码时只能联系平台级 Admin 处理。
- 来源：COM-0004、COM-0006、COM-0007
- Figma影响：平台级 Admin 用户管理需要提供创建用户、设置初始密码和设置新密码的任务；创建成功结果直接显示 active，不增加二次启用步骤。Organization admin 不出现这些全局操作；登录页和普通用户个人设置不提供忘记密码、修改密码或自助重置入口。
- 依赖：R-0002、R-0003、R-0014、R-0017
- 冲突：none
- 替代：开源版邀请用户与普通用户自助密码管理
- 首次进入：L-0002
- 最后变更：L-0003
