### 已确认决定

#### 产品边界

- 开源首版重点建设用户、组织关系、文档权限和知识库权限，弱化传统 ERP/IAM 的密码、审批、策略和审计能力。
- 当前主题不设计 RAG 编排、Harness、Agent、文档编辑器实现、知识切片和索引。
- Organization 是默认隔离边界；开源首版不允许跨 Organization 直接共享文档或知识库。
- 外部用户只需平台账号即可成为 external Project member，并通过 Project 明确授权获得项目资源权限。
- Project 只保留 active、suspended、archived 三种状态；创建后直接 active，suspended 可恢复，archived 代表项目完成并进入不可恢复的只读归档。
- Project archived 后，既有成员仍可查看历史文档和知识库，但不能编辑、新增成员或新增授权。

#### 用户与组织

- User 是平台全局身份，可加入多个 Organization 和任意多个 Department。
- 平台级 Admin 直接创建用户、设置初始密码和新密码；用户创建后立即 active。
- 普通用户不能修改密码，也不支持忘记密码或自助重置。
- 密码轮换、首次登录改密和唯一 Admin 的部署恢复不进入当前产品需求。
- 用户退出 Organization 后，该 Organization 的全部权限失效，包括 User 直授权和个人知识库。
- 用户退出 Department 或 Project 后，相应成员路径提供的权限立即失效。

#### 文档管理平台

- 文档管理平台中的 ManagedDocument 与知识库中的 KnowledgeDocument 是不同对象。
- A Department 把正式文档共享给 B、C Department 时，分别形成 B、C 独立文档分支。
- B 的修改、草稿、审核和版本只属于 B，不自动影响 A、C。
- 只有 editor 和负责人可以查看草稿；其他 viewer 在新版本发布前继续查看上一正式版本。
- 多名 editor 共同编辑同一草稿，系统不得静默覆盖或丢失他人修改。
- 任意参与编辑者可以提交审核；提交后暂停编辑，审核退回或提交人撤回后重新开放。
- 审核通过形成不可直接改写的正式版本；历史版本可查看、下载并恢复为新草稿。
- 接收部门负责人可以选择把源文档新版本拉取为本部门新草稿，不自动覆盖当前正式版本。
- 源文档删除或停止共享后，接收部门已经创建的文档分支继续保留并显示来源状态。
- 接收部门负责人可以把本部门审核后的正式版本再次共享，接收方获得新的独立分支。

#### 知识库管理平台

- KnowledgeBase 分为 Organization、Department、Project 和个人四类，最终所有权均在 Organization。
- Department、Project 和个人知识库分别有日常负责人；Organization owner/admin 可以查看和管理本 Organization 内全部 KnowledgeBase，平台级 Admin 可以管理全平台全部 KnowledgeBase。
- Project 与 KnowledgeBase 只保留明确授权，不使用含义不清的“关联”。
- KnowledgeBase 内容权限只使用 viewer/editor，管理、审核和共享由对应负责人承担。
- KnowledgeBase editor 是内容变更提交者，可以提交新增、更新和移除 KnowledgeDocument，但不能直接修改已生效正文、管理授权或执行审批。
- editor 提交的新增、更新和移除由对应日常负责人简单批准或拒绝；负责人、Organization owner/admin、平台级 Admin 和个人知识库所有者在各自管理范围内操作时直接生效。
- 知识库负责人可以直接授权和撤销，不进入额外审批。
- 用户能够查看正式 ManagedDocument 且具有目标 KnowledgeBase editor 时，可以发起加入知识库。
- Organization、Department、Project KnowledgeBase 由目标负责人简单批准或拒绝；发起人可在处理前撤回。
- 个人 KnowledgeBase 加入文档不需要审批。
- KnowledgeDocument 是加入时正式版本的独立快照，源文档修改或删除不自动影响知识库副本。
- 文档正式版本发布后不自动更新知识库，由相应负责人选择更新哪些知识库。
- 更新 KnowledgeBase 会创建新的 KnowledgeDocument 版本，旧版本保留。

#### 权限与查询

- 开源首版删除 blocked/禁止访问，只保留允许授权和撤销。
- 同一用户有多条允许路径时，任意有效路径可提供权限；撤销一条路径不影响其他路径。
- 权限变化成功后，所有新请求立即使用最新权限结果。
- 普通用户只查询本人权限；Department、Project 和个人知识库负责人查询自己管理资源的使用者及权限。
- 平台级 Admin 是全平台超级管理员，可以查看和管理全部 Organization 及其所有资源内容。
- Organization owner/admin 是组织范围内的超级管理员，可以查看和管理本 Organization 的全部资源，包括下级 Department、Project、个人文档、个人知识库及其中的文档，但不能访问其他 Organization。
- 个人知识库中的“个人”表示普通成员默认不可见，不对 Organization owner/admin 或平台级 Admin 隐藏。

#### 开源版流程

- 文档审核只保留提交、负责人通过/退回、提交人处理前撤回。
- 文档加入非个人知识库只保留申请、负责人批准/拒绝、发起人处理前撤回及实际写入结果。
- 不提供多级审批、审批策略引擎、审批转交或审批过期。
- 审计仅保留解释成员、授权、文档审核、版本和知识库更新所需的最小操作记录。
- Figma 可决定页面和交互表现，但不能改变资源归属、分支隔离、草稿范围、审核条件、版本结果、知识库更新选择和权限失效规则。
