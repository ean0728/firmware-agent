### 已确认决定

- Organization 是知识资产最终所有权和默认隔离边界；Project 只建立协作及授权关系。
- User 是平台全局身份，可加入多个 Organization，并在不同 Organization 中具有不同组织角色。
- 用户可以同时属于任意多个 Department，不强制主部门和兼职部门模型。
- Project 支持跨 Organization 的 external member；加入项目不自动取得项目所属 Organization 的其他资源权限。
- Organization 治理角色不自动等同于 KnowledgeBase/Document 读取权限；没有可证明授权路径时默认拒绝。
- KnowledgeBase 支持 viewer、editor、manager、blocked；可向 Organization、Department、Project 或 User 授权。
- Document 默认继承 KnowledgeBase 权限，并允许文档级直接授权、权限提高和 blocked；KnowledgeBase blocked 不能被文档直授权反向解除。
- 共享不转移资源所有权；授权可以设置有效期并撤销，撤销单一路径不影响其他仍有效的授权路径。
- 开源版不使用邀请流程。平台级 Admin 直接创建用户、设置初始密码和新密码；普通用户不能修改密码，也不支持忘记密码或自助重置。
- 平台级 Admin 创建用户成功后，账户立即进入 active，无需再次启用。
- 授权审批的 approved 与权限已经生效的 applied 必须区分。
- 授权生效失败时，平台级 Admin 可处理全平台任务，Organization owner/admin 可处理本组织任务；申请人和审批人只能查看。
- Project completed 后保留既有项目来源授权但禁止新增；Project archived 后撤销项目来源授权，其他独立授权路径不受影响。
- Department 存在有效授权时禁止直接归档；必须先查看影响并迁移、转换或撤销全部有效授权。
- 授权服务不可用时，所有受保护的页面、API 和 RAG 查询统一拒绝，不使用缓存允许结果降级。
- Figma 可以决定页面结构、导航、控件、布局、视觉和动效，但不能改变产品规则和用户结果。
